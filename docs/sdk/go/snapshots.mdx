## Group lifecycle and 0.8 migration

`Snapshot.Get` returns a named `SnapshotGroup`; `Checkpoint.Open` returns an immutable `SnapshotArtifact`. Create a new group through a sandbox or sandbox handle, then capture later checkpoints through that group. The initial call refuses an existing group; an append uses its saved source identity. Imported or orphaned groups cannot capture, and recreating a sandbox with the same name does not rebind them.

<Accordion title="Example">

```go
source, err := m.GetSandbox(ctx, "worker")
if err != nil { return err }
created, err := source.Snapshot(ctx, "history", m.WithSnapshotCaptureConfig(
    m.SnapshotCaptureConfig{Name: "ready", RecordIntegrity: true}))
if err != nil { return err }
group := created.Snapshot
next, err := group.Checkpoint(ctx, m.WithSnapshotCaptureConfig(
    m.SnapshotCaptureConfig{Name: "after-build"}))
if err != nil { return err }
exact, err := group.GetCheckpoint(ctx, "ready")
if err != nil { return err }
if _, err = group.SetHead(ctx, "ready"); err != nil { return err }
if _, err = group.ClearHead(ctx); err != nil { return err }
// Clearing selection keeps all checkpoints; use an exact member to spawn.
child, err := exact.SpawnSandbox(ctx, "child")
if err != nil { return err }
reopened, err := m.Snapshot.Get(ctx, "history")
if err != nil { return err }
```

</Accordion>

The initial result is `SnapshotCreateResult` with the group, exact first checkpoint, and operation-owned head outcome. A later capture returns `CheckpointCaptureResult` with its exact checkpoint and head outcome. Read the checkpoint from that result when you need the artifact created by your call; another caller may already have moved group head. An omitted member name is generated. Capture is disk-only by default; full capture and integrity recording are explicit options.

`head` returns no checkpoint after explicit clearing. Listing members and exact member lookup still work. Selecting or clearing the current value is a reported no-op. New groups are bound to one sandbox instance, while one sandbox may have several groups. Existing group destinations cannot be changed by capture options.

Artifact helpers formerly owned by `Snapshot` are now accessed through `Checkpoint`. Existing `SnapshotHandle`, builder, archive, ID, and verification type names remain; this public object rename does not rewrite persisted artifact IDs. Retained artifact helpers below also cover supported cloud workflows, where local group operations return unsupported.

Group spawn selects head once and retains that member while preparing the destination. Checkpoint spawn uses its exact receiver, even if group head later changes. Default full checkpoints resume execution; disk checkpoints boot fresh. The destination configuration and progress APIs use the existing restore preparation; source selectors cannot be changed by a destination callback.

## Save an exact checkpoint

<Accordion title="Example">

```go
if err := checkpoint.Save(ctx, "ready.msb"); err != nil { return err }
if err := checkpoint.Save(ctx, "portable.msb", m.SnapshotSaveOptions{WithParents: true, WithImage: true}); err != nil { return err }
```

</Accordion>

The receiver selects one immutable checkpoint. Use the group’s optional head or exact-member lookup first; saving a group’s whole history is not implied. The no-options call writes a compressed `.msb` archive. `SaveTo` retains its explicit options form for compatibility. See the archive compatibility option below before sending output to an older reader.

## Group archive import

<Accordion title="Example">

```go
Snapshot.Load(ctx, group, files)
Snapshot.Load(ctx, group, files, SnapshotImportOptions{Dest: "store", Base: "base.msb", SetHead: true})
```

</Accordion>

`files` is `[]string`; at most one `SnapshotImportOptions` value is accepted. It contains `Dest`, `Base`, and `SetHead`; the group is selected only by the positional argument. Legacy `Checkpoint.LoadWithOptions` and `Checkpoint.LoadMany` retain `SnapshotLoadOptions`, including its `Group` field. Returns `(*SnapshotImportResult, error)` with `Snapshot`, `Checkpoints`, `Added`, `Reused`, `HeadUpdate`, `OperationID`, and `Warnings`.

The result contains every unique supplied checkpoint, including bundled dependencies, in stable ID order. `Added` and `Reused` identify what was new versus already installed at publication; archive argument order does not select the head. The head outcome belongs to this operation and does not change when another operation edits the group. Multiple incomparable tips can commit a headless group; explicit head selection refuses ambiguous tips.

A successful return confirms publication and catalog completion. Warnings describe deferred cleanup after commit. A structured import error distinguishes no publication, confirmed publication with a later failure, and an unknown outcome needing recovery. Import never binds a group to a source sandbox. See [atomic import requirements](/cli/snapshot-commands#msb-snap-import) for filesystem capabilities and maintenance requirements.

## Group inspection

```go
func (g *SnapshotGroup) Inspect(ctx context.Context) (*SnapshotGroupInfo, error)
```

Returns the group's name, backend path, optional head, member count and optional saved source binding. Head and count come from one protected metadata read. Field names include `CheckpointCount`, `Source.RecordedName`, `Source.CurrentName`, `Source.DatabaseUUID`, `Source.SandboxID`. The source is absent for an unbound history; otherwise its status is `available`, `missing_sandbox` or `different_catalog`. Saved and current names distinguish renames; identity is the catalog UUID plus sandbox row ID, so deleting and recreating the same name does not rebind the group.

Source availability is observed separately from group metadata and is not a guarantee of later capture readiness. Inspection does not change the selected head or create a missing catalog identity. Invalid metadata and database failures remain errors, rather than being reported as unbound. Obtain a member with `GetCheckpoint` for its immutable metadata.

## Group verification

`group.Verify(ctx)` checks every pinned member and returns `(*SnapshotGroupVerifyReport, error)`. `State` distinguishes `complete`, `incomplete`, `invalid`, and `empty` (zero checked). `Checkpoints` contains each member's `ID`, `Path`, `State`, optional existing `SnapshotVerifyReport`, and `Findings`; `PayloadHashes` counts physical hash passes. Headless groups are valid verification targets. To verify only head, obtain the optional checkpoint and call its `Verify(ctx)` method.

Unrecorded checksums return incomplete coverage. Corruption, missing files, unsupported requirements, and operational failures return a `*SnapshotVerificationError`; use `errors.As` and inspect its `Report` for every selected member. Errors before meaningful selection retain the ordinary error type. Shared physical payloads are hashed once per algorithm; independent copies are checked separately. Cancellation retains reader protection until the hashing worker finishes.

## Whole-group removal

```go
func (g *SnapshotGroup) Remove(ctx context.Context) (*SnapshotRemoveResult, error)
```

Removes the selected history and returns `SnapshotRemoveResult` with `Group`, `Removed`, `HeadUpdate`, and `Warnings`. The member IDs and cleared-head outcome belong to this operation. Empty groups can be removed. Active readers and surviving external dependents refuse removal; there is no force bypass for an entire group.

If publication commits but catalog cleanup fails, the call raises or returns `SnapshotGroupRemovalRecoveryError` with `Result` and `Detail`. The attached result means removal already happened. Cleanup warnings after successful catalog reconciliation are returned in the result. An uncertain durability outcome is an error requiring recovery rather than a claimed successful removal. Later listing recovers pending cleanup without deleting a replacement group.

## Exact checkpoint removal

<Accordion title="Example">

```go
removed, err := checkpoint.Remove(ctx)
forced, err := checkpoint.Remove(ctx, m.CheckpointRemoveOptions{Force: true})
```

</Accordion>

These are alternative calls, not successive removals of the same checkpoint. The instance method removes the retained checkpoint identity, refuses a replacement at the same address, and returns `CheckpointRemoveResult` with `ID`, optional `HeadUpdate`, and `Warnings`. The head outcome belongs to this operation; later head edits do not change it. Removing the head selects its surviving same-group parent or clears selection. Removing another member reports an unchanged head. Standalone artifacts have no head outcome.

Force permits removal despite indexed children, but never bypasses reader protection. A repeated removal reports a missing checkpoint rather than fabricating another successful result. Backends or native libraries without exact-removal reporting return unsupported instead of falling back to deletion by name.

If removal commits but catalog cleanup fails, the call returns `*SnapshotRemovalRecoveryError`, with `Result` and `Detail`. Its result is authoritative: removal already happened. Recover the affected storage before retrying cleanup; do not assume an error means the checkpoint still exists.

## Capture recovery

A failed capture can still have published its requested artifact before source recovery failed. `SnapshotSourceRecoveryError` preserves the source checkpoint recovery locator and, when publication completed, the published artifact’s kind, path, identity, digest and `HeadUpdate`. The head outcome belongs to that publication even if another operation changes the group afterward. Archive-only capture and older producers omit it; do not infer it by reading the current head. Inspect those details before retrying or removing the source. The error does not prove that the source is running or safely paused.

## Guest writeback

Set `SnapshotCreateOptions.GuestFlush` to `msb.GuestFlushRequired`, pass `msb.WithForkGuestFlush(msb.GuestFlushRequired)` to `Fork`/`ForkMany`, or call `source.PauseWithGuestFlush(ctx, msb.GuestFlushRequired)`. The default `GuestFlushAuto` flushes live disk-only captures, but adds no optional flush to full captures, forks, or pause. `GuestFlushSkip` retains mandatory storage barriers. A paused disk capture needs a matching prior flush; cloud rejects non-Auto policies. See [guest flush policy reference](/sandboxes/snapshots#guest-flushing).

Disk capture, including `SandboxHandle.Snapshot`, requires a native library that supports guest-flush policies. Older libraries return an upgrade-required error, including for stopped disk captures. Full Auto capture and unrelated operations retain their compatibility.

### Import options

Legacy options for `Checkpoint.LoadWithOptions` and `Checkpoint.LoadMany`. Canonical `Snapshot.Load` uses `SnapshotImportOptions` with the same destination/base/head controls and no `Group` field.

| Option | Purpose |
| --- | --- |
| `Dest` | Parent directory containing groups. Defaults to the local snapshot store. |
| `Base` | External snapshot or standalone archive for missing dependencies. |
| `Group` | Destination group. Omit to create one group for the import. |
| `SetHead` | Select the imported tip, even with divergent ancestry. Defaults to false; requires a unique tip. |

With divergent tips, the existing head stays selected; a new group has no head. Select a member explicitly. Identical members may be reused; conflicting identities fail. See [archive imports](/sandboxes/snapshots#import-archives).

## SandboxHandle

<span id="handle-snapshot" />

```go
func (h *SandboxHandle) Snapshot(ctx context.Context, group string,
    opts ...SnapshotCaptureOption) (*SnapshotCreateResult, error)
```

The first positional name selects the new group. Use the initial-checkpoint option to name its first member, then call the returned group’s checkpoint method for subsequent captures. ## Restore

Restore into a new detached sandbox. Disk boots fresh; full resumes execution. See [restore examples](/sandboxes/snapshots#disk-snapshots) and [progress](/sandboxes/snapshots#restore-progress).

<Accordion title="Example">

```go
child, err := m.RestoreSandbox(ctx, "api:baseline", "api-restored", m.WithCowMemory())
```

</Accordion>

| Control | Purpose |
| --- | --- |
| `WithCowMemory()` | Share unchanged full-snapshot memory. |
| `WithForked() / RestoreConfig.Forked` | Deprecated alias for the same CoW memory policy; see [migration notes](/sandboxes/snapshots#migrating-restore-options). |
| `WithSnapshotDiskOnly()` | Boot only the saved disk. |
| `WithSnapshotBase(base)` | Supply an archive dependency. |
| `RestoreSandbox` | Return the restored sandbox. |
| `RestoreSandboxWithProgress` | Return event and result channels. |

Image, replacement, and startup-command options are not accepted. Full restore requires matching CPU and memory settings, keeps captured network devices, and cannot apply a new guest security profile. Use disk-only restore to change these.

Restore rejects missing external filesystems (and, for full restore, additional disks) by default. Use `WithAllowMissingResources()` to resume with unavailable devices (full restore records warnings). This is separate from strict/relaxed validation of supplied mappings; inheritance does not waive missing backing. Root and owned storage remain required.

<Accordion title="Destination options">

| Option | Purpose |
| --- | --- |
| `WithRestoreCPUs, WithRestoreMemory` | CPU count and memory in MiB. Full restore must match capture. |
| `WithRestoreNetworkPolicy` | Replace host traffic filtering; guest DNS and TLS settings stay unchanged. |
| `WithRestoreMaxConnections` | Concurrent TCP limit; zero means unlimited. |
| `WithRestoreDisableNetwork` | Remove the NIC. Rejected for full snapshots that captured one. |
| `WithRestoreSecurityProfile` | Guest security profile. Disk boot only, including an explicit default profile. |
| `WithRestoreMaxDuration, WithRestoreIdleTimeout` | Lifetime and idle limits. Omitted means unlimited; zero expires immediately. |
| `WithRestoreGuestClock` | `GuestClockSync` or `GuestClockOff`; omission preserves a recorded policy, defaulting to sync when absent. |
| `Ports` | Bind destination TCP or UDP ports. |
| `Vsock` | Bind destination vsock endpoints. |
| `User, LogLevel` | Default user for new execs and host runtime log level. |
| `WithDangerouslyInheritResources` | Explicitly inherit host resources. Disabled by default. |
| `WithExternalMountPolicy` | Validate supplied filesystem mappings: strict (default) or relaxed. Does not grant access. |

Omitted controls retain destination defaults. Durations use `time.Duration`, rounded up to seconds. Binding fields belong in `WithRestoreConfig(RestoreConfig{...})`; nil pointers mean omitted. Network policy accepts factory results or `NetworkConfig` with only `Rules`, `DefaultEgress`, and `DefaultIngress`.

Full capture records the source clock policy; current disk capture does not. An explicit sync policy overrides a saved off policy. The same option is available on group and checkpoint spawn, including progress variants. Clock selection controls guest wall-clock synchronization. Unsupported native SDKs or runtimes refuse unsupported explicit selection before launching the destination.

</Accordion>

## Compaction

Compact a local sandbox’s root or owned disks. See [compaction](/sandboxes/snapshots#compact-disks) for examples and recovery requirements.

<Accordion title="Options and results">

| Option | Purpose |
| --- | --- |
| `Disk` | Select one owned disk by guest path; `/` selects the root. |
| `RootDiskOnly` | Select only the root. Cannot combine with the disk selector. |
| `Layers` | Oldest sealed layers to merge, including the base. Minimum two; omit for all. Excludes the writable layer. |
| `DryRun` | Preview without changing storage. |

Defaults to the root and owned data disks; excludes named/external volumes and directories. Requires a running or fully stopped local sandbox. Fewer than two sealed layers means no change; no eligible disks returns an empty result with zero counts.

Results include aggregate counts and per-disk entries keyed by `GuestPath`. `MaterializedBytes` counts copied bytes, not reclaimed space. Times are microseconds: per-disk `TotalUs` covers preparation; aggregate `TotalUs` also includes switching; `PauseUs` measures the shared VM pause.

</Accordion>
