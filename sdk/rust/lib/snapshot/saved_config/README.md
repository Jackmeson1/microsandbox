# Saved configuration selection

This module implements runtime, resource, execution, storage, network-policy, keyed secret/listener and gateway-input selection stages, plus runtime binding preparation of PR3's saved-config resolver. It is not called by snapshot capture, sandbox launch or exec yet. The required saved-config extension remains unsupported until the complete consumer and capture paths are integrated in this PR.

`select_runtime_defaults` accepts validated portable runtime metadata, the existing sparse `SandboxSpecPatch`, structural clear selectors and trusted operation facts. It returns the surviving lower-priority saved overlay, unresolved binding consumers, unknown fields and full-resume script identity obligations. The explicit destination patch stays separate, so this stage cannot copy destination credentials or scripts into portable metadata.

Native collection replacement and merge are distinct. An empty merge preserves saved environment entries; an empty replacement removes the optional saved map. Per-key merge removes only the overridden source entries. The generated `replaces_*` patch accessors expose existing replacement intent without changing patch application or serialization. Config-file decoding retains its released merge behavior.

Clears are validated against the original source before any are applied. Repeating a key clear or combining it with a whole-map clear is order-independent. Missing keys and unavailable map contents produce a redacted error; clearing the whole optional field can discard unknown contents. Map keys containing dots remain literal keys.

Fresh disk boot discards optional defaults. Fresh full resume still retains captured init, hostname, script backing and clock evidence. This stage rejects a new initial command or init/hostname overrides during full resume. Script replacements retain the original evidence and return identity proof obligations, including empty whole-map replacement; they are never approved merely because this selector succeeds. No script is executed here.

The approved saved-snapshot rule clears saved CMD when an explicit entrypoint differs from the recorded literal entrypoint and no explicit CMD is supplied. An identical recorded literal entrypoint retains CMD; an unavailable or binding-backed entrypoint cannot prove equality, so an explicit replacement resets inherited CMD. Explicit CMD, including an empty vector, always wins. `reset_inherited_cmd` must also block older image CMD fallback during final assembly. Fresh mode already discards saved CMD, and existing image-only merging remains unchanged. The internal policy-choice switch has been removed; launch integration is still required.

Integration must still resolve bindings at their actual consumer's activation time, enforce mandatory destination/security policy, preserve captured resource compatibility, validate full-state script backing, and apply the original destination patch in its existing order. Saved generated hostnames require destination identity regeneration. Optional-field clears must be reconciled with image and legacy defaults during final assembly. These responsibilities are not fulfilled by returning a surviving overlay, and import/inspect success does not authorize execution.

## Resource and execution selection

`select_resource_defaults` reuses optional active allocations for disk boot and checks the combination of explicit values and retained saved maxima. It keeps unknown observations distinct. Full resume takes construction geometry separately from the already checked execution closure, accepts only the existing equal-geometry overrides and refuses resource clears or THP overrides. Fresh mode cannot discard that geometry. Host CPU placement and source profile names never enter the required geometry patch. Complete document validation must precede selection, and final assembly must still validate destination defaults, host capabilities and managed limits.

`select_execution_defaults` handles user labels, ordered rlimit replacement and independent lifetime fields. Lifetime output distinguishes omitted defaults from unknown values, concrete zero and concrete unlimited (`Value(None)`). Clearing or overriding one duration leaves the other unchanged. The output contains no elapsed timers or ephemeral ownership. These settings affect new processes and new destination timers; full-resume processes retain their captured state.

Security admission takes destination baseline and mandatory minimum from trusted destination policy, never from the artifact. A saved weaker profile requires explicit destination intent, and explicit intent cannot bypass the mandatory minimum. Unknown disk-boot policy requires a choice, a clear or fresh mode. Full resume requires independently established captured security evidence, retains existing refusal of profile overrides, checks recorded/captured consistency and rejects incompatible destination policy even in fresh mode. The selector does not obtain that evidence or install enforcement itself; activation remains disabled until capture and all consumer paths supply and enforce the complete contract.

## Storage and IPC selection

`select_storage_inputs` matches native destination mounts by canonical guest path and socket routes by `(port, socket_type)`. It retains every other required source resource, including when the explicit list is empty or mode is fresh. A shared binding ID stays required until every corresponding mount/route consumer has a destination mapping. Destination host paths and endpoints remain separate from saved metadata, keep their original path-resolution policy, and are not opened or created by selection. Duplicate destination identities reject with value-safe errors; parent mounts precede children.

Authoritative owned backing is retained even when the saved mount section is omitted or unknown. It cannot be replaced by an explicit mount, and new disk-boot owned mounts are checked for collisions with captured and other new owned IDs. Legacy external guest paths remain requirements; an empty tmpfs or new owned volume does not satisfy missing external backing. Contradictory complete saved and legacy inventories reject. Missing/unknown metadata is never inferred to be a complete inventory from a partial destination mapping.

Full resume rejects new resources when the recorded inventory is complete, new backing provisioning, obvious filesystem/block conflicts, incompatible known disk format/filesystem, changed mount flags/ownership, and tmpfs geometry changes. Every successful full plan still requires authoritative physical identity and captured-topology validation. Named-volume kind, file/directory identity, open handles, unresolved filesystem probes and real socket compatibility cannot be proved from a path match. The full checker must inspect all captured resources even when the saved inventory is incomplete.

Saved metadata relaxation, host permission mirroring and root-symlink following produce field-specific approval requirements; they are not granted by the artifact. Explicit mappings retain their own input provenance and must still satisfy mandatory destination policy. Narrow existing missing-resource or filesystem-identity waivers belong to later operation admission and must not erase owned state or turn absent resources into new empty backing. The output is a plan with unresolved bindings/approvals, not an activation-ready configuration.

## Network policy selection

`select_network_policy_defaults` emits a native lower-priority policy patch for NIC intent, ordered rules, DNS protection/timeouts, TLS inspection/verification, connection caps, per-direction rate limits, NAT64 classification and denial responses. Explicit sparse inputs mask only the fields they supply; ordered rule, bypass, scoped-verification and prefix lists replace in full. False, zero and empty values are preserved. The source section validates before fresh mode or overrides can mask malformed records.

Known absence, builtin default and unavailable observation remain distinct from an omitted source field. `absent_fields` records concrete missing rate directions/messages that a native sparse patch cannot express; `defaulted_fields` preserves recorded builtin choices. `cleared_fields` records explicit structural clears. The policy assembler processes these operations before the explicit layer, rather than applying only `defaults` and accidentally reviving an inherited message or rate limit. Combined network assembly preserves those results alongside resource inputs; mandatory destination-policy enforcement remains a later gate.

The destination supplies its inspection baseline. Selected saved TLS/DNS/QUIC relaxations, bypass scopes, reduced intercepted ports and relaxed authority return individual approval obligations. Explicit destination values mask the corresponding saved obligation but still need mandatory-policy enforcement after full assembly; the absence of an obligation is not an authorization result. Debug output excludes saved policy/message values and destination endpoints.

Fresh disk boot discards these optional policy defaults. Full resume retains recorded NIC presence and rejects conflicting overrides or a presence clear; even matching or unknown values still require independently checked captured NIC, identity, trust and connection state. Ordinary host policy selection cannot establish that evidence, and fresh mode cannot waive it.

This stage neither fulfills nor drops DNS/proxy/CA/listener/secret bindings. The separate input selectors and binding-demand planner below feed resource preparation, destination enforcement and full-state checks. Its output contains no host resolver endpoints, source addresses, trust-file paths, credentials, secret entries, allocated guest identity, source profile names or certificate cache state. The complete feature remains disabled until these stages and every activation/exec path are integrated.

## Binding demand and supply gaps

`plan_binding_demand` combines selected typed consumers with a separately established captured-execution inventory. Cold init, script backing, gateway, trust, listener, mount and IPC uses require inputs before their selected activation; a new-command use is immediate for run and otherwise retained for future exec. Shared IDs keep the strongest timing and every consumer. Full resume does not replay init, but keeps its bindings for a later cold boot. Captured requirements remain immediate even when fresh mode or explicit command overrides removed the corresponding launch default. An unavailable captured inventory is not treated as a checked empty inventory.

`BindingDemandPlan::supply_gaps` checks destination value kinds and reports missing immediate, future-command and later-cold-boot inputs without storing any credential values. These sets can overlap: satisfying an immediate shared input does not erase the future requirement from the plan. Unknown input IDs, kind conflicts, malformed identifiers and oversized combined inventories fail with value-safe diagnostics; debug output prints counts only. The original typed inventory still needs complete-document validation, and pending next-start bindings must never be passed as selected active requirements.

This is planning/admission metadata, not an authorization to execute. Gateway consumers must come from the selected effective network configuration, never a blanket declaration that all recorded settings are active. Binding materialization, keyed network selection, physical identity checks, mandatory policy, coherent capture and persistent deferred enforcement still need integration. Every exec and later cold boot must re-evaluate its requirements against its actual explicit inputs. The required extension and production capture/launch/exec paths remain disabled until the entire contract is implemented.

## Keyed secret selection

`select_secret_inputs` matches already selected substitution requirements against explicit destination entries by the exact environment key. A new value for one key does not drop another key or its binding, including when both share one logical ID. Explicit empty collections do not erase selected requirements; optional clears/mode selection happen before this step, and independently established captured uses still join binding demand afterward. Combined duplicate placeholders reject, so replacing one key cannot accidentally redirect another surviving placeholder to a different secret.

Full resume rejects a changed known placeholder for an existing key and always retains a captured-state proof obligation. New explicit entries are destination policy/future-command defaults, never instructions to rewrite the environment of captured processes. Missing or unknown source metadata stays unknown even when explicit inputs exist. Recorded builtin policy, absent global passthrough and explicit empty policy are kept distinct for final assembly.

Selected destination `SecretEntry` values remain local inputs and are not serialized into portable metadata. The global-default patch contains no secret entries. Debug/errors omit credential values, source names and placeholders; saved TLS-identity relaxations produce field-specific approval obligations. An explicit relaxation still requires mandatory destination-policy admission. No host credential source is read, no gateway policy is installed, and no captured connection is authorized by selection alone. Binding materialization, listener/proxy/trust preparation, assembly, coherent capture and all activation/exec enforcement remain required before enabling the saved-config workflow.

## Listener and gateway input selection

`select_listener_inputs` preserves each logical listener/transport identity, including multiple listeners targeting one guest service. A logical destination binding supplies its host address/port without copying source-host ownership. Native port inputs match a remaining saved guest service/transport only when the match is unambiguous on both sides; ambiguous mappings require logical binding IDs. Binding one listener does not erase another, and supplying TCP alone does not satisfy UDP sharing its ID. Additional native listeners remain separate. Exact destination collisions use parsed IP identity; port-zero requests remain unallocated inputs. Actual bind admission, wildcard/dual-stack conflicts, host policy and captured connections still need checking.

`select_gateway_inputs` separates resource inputs from policy defaults. Explicit ordered DNS and CA lists replace the corresponding selected requirements, including empty lists, while policy-only patches leave those requirements intact. Shared CA bindings retain unsupplied scoped/guest-trust consumers. An explicit host-trust boolean cannot establish a particular recorded certificate's identity. Explicit proxy clear stays distinct from omission and cannot arise implicitly from missing credentials. Interception certificate/key inputs retain the engine's all-or-neither contract; auto-generation intent is a destination input, never proof of compatibility with captured trust.

Both selectors run without sockets, DNS resolution, filesystem reads or credential lookup. Paths and credential sources remain destination inputs with their existing resolution policy. Unknown and builtin defaults remain distinct; original metadata and cross-field binding kinds are checked before overrides can hide malformed requirements. Full resume always retains a separate compatibility obligation, and independently established captured uses must still join binding demand after selected defaults are replaced. None of these outputs authorizes guest activation or serializes destination secrets into snapshot metadata. Whole-destination input composition is described below. Materialization, coherent capture/retention, admission and every activation/exec consumer remain unfinished.

## Runtime input preparation

`prepare_runtime_inputs` resolves selected text bindings into transient, redacted consumer inputs. It preserves complete argv ordering, empty arguments and exact environment keys, with no shell expansion, host lookup or script wrapping. If a future-command binding is missing, the whole corresponding field stays deferred; it never returns a shortened argv or a partially populated environment as ready. Initial commands, cold-boot init and script backing require their selected inputs immediately. Full resume can retain init requirements for a later cold boot without replaying PID 1.

Inline scripts retain their validated exact bytes and mode. A destination input supplying an excluded script body must also provide explicit permission bits; preparation never assumes the ordinary startup writer's `0755` mode. Script bytes and mode remain separate from ordinary runtime script strings so later materialization can preserve them exactly. Full-resume overrides and empty script-map replacements still carry their captured-backing identity obligations. This internal input contract does not yet add a public CLI binding syntax.

Resolved destination text uses zeroizing buffers and is never converted into portable literal metadata. The retained configuration keeps its original binding references for later exec, cold boot and capture provenance. Debug output and errors omit values and binding IDs. Omitted, builtin-default, unknown, explicit-empty and unresolved states remain distinguishable. Expanded input budgets count each use of a shared binding, preventing small metadata from expanding into unbounded arguments, environment or scripts.

This pure preparation step performs no file writes or guest execution. The complete assembler must still enforce combined selected/captured demand, mandatory destination policy, generated hostname identity and full-state compatibility, and persist deferred requirements for every later consumer. Supplying an init/env value here cannot discharge a separate captured-process requirement. Last-active configuration retention and coherent capture remain prerequisites; the production writer, launch and exec paths remain disabled.

## Native runtime assembly

`prepare_runtime_configuration` composes runtime selection, binding preparation and native runtime/env/init assembly. The lower input must already contain the resolved destination/image defaults; do not run image-default merging again on its output. Structural clears suppress the named lower fallback before explicit inputs apply. Complete saved env/script maps replace their lower maps, followed by the existing native destination per-key merge or full replacement. A changed entrypoint uses explicit empty CMD to prevent the image CMD from returning; ordinary image-only merging remains unchanged.

The result keeps native command defaults private until `command_defaults()` verifies that all selected command fields are available. Unknown or deferred values cannot expose an apparently usable image fallback or incomplete environment. Future command overrides reselect and reprepare from retained references. `cold_boot_init()` independently checks init availability and returns its resolved path/args/env for cold boot only; full resume must not replay that init. Generated hostnames are cleared for disk boot and retained as evidence for full-state identity checking.

Exact script backing stays in a separate bytes/mode map; native runtime script strings remain empty so the ordinary 0755 writer cannot silently change recorded permissions. Explicit native script replacement retains its existing 0755 behavior, and full-resume replacement still carries captured-backing proof obligations. Prepared binding buffers remain zeroizing; copies converted to existing native configuration types follow those types' ordinary local secret handling. Neither assembled plans nor retained portable metadata serialize destination credentials, but this is not a claim that every native string is zeroized.

This completes runtime field composition only. It does not assemble the other policy/resource sections, install backing, enforce mandatory policy, persist deferred requirements, capture last-active state or activate a guest. The production workflow and required-extension support remain disabled until those remaining paths are complete.

## Native network policy assembly

`prepare_network_policy_configuration` composes known portable policy fields over resolved destination defaults, followed by the explicit policy patch. Recorded builtin defaults and concrete absence reset the corresponding lower fallback. Structural clears run before explicit values, so false, zero, empty lists/messages and independent rate directions retain their meanings. Omitted source fields leave lower defaults intact; unavailable source observations cannot masquerade as known destination policy.

The plan keeps its native policy private. `apply_policy_to` refuses unknown selected policy before changing any destination field, then updates policy only while preserving separately prepared DNS endpoints, CA/key paths, proxy inputs, listeners, interface identity and secret entries. Neither lower nor explicit resource/credential inputs are copied into the policy plan. Errors and Debug omit policy values and destination inputs.

Recorded builtin TLS defaults retain approval obligations when they weaken the destination baseline; a default marker is not authorization. Literal saved relaxations retain their existing obligations, and full resume retains independent captured-network compatibility checks even in fresh mode. Applying policy does not discharge those obligations or enforce mandatory destination constraints. This completes policy-field composition only; resource preparation, full assembly, coherent capture/retention and all activation/exec gates remain required before enabling the saved-config feature.

## Native resource and execution assembly

`prepare_resource_configuration` composes sparse destination/image defaults, selected saved resources and explicit inputs. An omitted maximum follows the final boot allocation, matching existing SDK behavior; a configured maximum remains a ceiling and the assembled allocation must fit it. A recorded builtin maximum or explicit maximum clear removes the lower ceiling. Unknown source observations cannot borrow a pending allocation from lower defaults, and `resources()` refuses until they are resolved. Full resume uses independently checked construction geometry, retains THP/guest-policy compatibility obligations and never imports source host placement or profile names.

`prepare_execution_configuration` composes user labels, process limits, guest security and fresh lifetime durations. Complete saved label maps suppress obsolete lower user labels; native explicit merges and replacements retain their established meanings. Destination identity labels and ephemeral ownership survive application unchanged. Reserved identity keys in source or explicit user labels are rejected even when fresh mode or overrides would hide them. Unknown execution defaults prevent any destination mutation. Process limits preserve ordering and full-width unlimited sentinels, and zero durations remain distinct from unlimited durations. This sets configuration only: limits apply through the existing cold-boot/new-process mechanisms, and full resume must not rewrite captured processes or reuse source elapsed timer counters.

These plans expose no portable serialization of destination inputs, and their diagnostics redact values. They complete resource and execution field composition, not runtime activation: destination capacity/policy admission, captured-state validation, binding/backing preparation, coherent last-active capture, and every launch/exec consumer remain required. The saved-config writer and required-extension support stay disabled until the complete workflow is implemented.

## Gateway binding preparation

`prepare_gateway_configuration` turns selected resolver, certificate, interception-identity and proxy bindings into destination-only native inputs. Ordered resolver and trust lists remain ordered. A certificate shared by upstream, scoped and guest trust consumers is supplied once but retained for each consumer. Explicit resource replacements and empty lists mask only their own requirements; builtin choices reset lower resource defaults. Unknown observations prevent application before any destination mutation, and every missing immediate input refuses preparation. Proxy protocol and credential shape must agree; missing credentials never select an unauthenticated fallback.

The plan retains logical source requirements and full-state compatibility obligations. It neither opens files nor resolves credential sources, and preserves path spellings for the existing destination path-resolution layer. Guest trust files remain a separate installation obligation; a host-trust boolean does not satisfy them. Native network validation, file/certificate loading, secret-source resolution, mandatory destination policy and authoritative full-resume identity checks must still run before activation. Debug/error output redacts values, resolved destination inputs are not serialized into portable metadata, and expanded shared bindings have a total size budget. The saved-config workflow remains disabled until coherent capture and every enforcement/consumer path are integrated.

## Substitution binding preparation

`prepare_secret_configuration` composes the complete selected placeholder inventory into native substitution entries. Each surviving saved binding requires destination material or a destination-owned credential source; keyed explicit overrides replace only their own entries. Shared binding values expand per consumer without changing each consumer's placeholder, allowed hosts, substitution locations, passthrough rules or violation policy. Explicit empty lists do not erase selected requirements. Recorded builtin inventory resets lower entries, and unknown inventory refuses before destination mutation.

Inline destination material is held in zeroizing values. Environment and store references remain unresolved for the existing destination resolver; preparation never reads the source host or copies credentials into the portable record. Missing/extra bindings, ambiguous value-plus-source inputs and excessive expanded credentials fail with redacted errors. Empty explicit material stays distinct from a missing source. Global policy preserves recorded absence and explicit empty-list semantics.

The immutable selection retains logical requirements, field-specific TLS identity approvals and independent full-resume placeholder/connection obligations. Preparation is not policy authorization or proof that a destination credential is available. Credential resolution, mandatory policy, captured-state checks, coherent capture/retention and every activation/exec consumer remain required; the saved-config writer and public activation stay disabled.

## Storage and IPC binding preparation

`prepare_storage_configuration` converts selected guest resources into native destination mount and socket inputs. Bind files/directories, existing named directory/disk volumes, external images and stream/datagram endpoints have distinct binding kinds. A logical binding can supply several consumers while each retains its own guest path, flags, quota and socket port. Explicit per-resource mappings replace only their own consumer; empty lists and fresh mode cannot discard other required backing.

Named bindings never imply creation, ensure-exists or resizing. Recorded capacities, quotas and backing kinds remain in the immutable selection for actual resource admission. Authoritative owned-volume configuration is reconstructed from the captured inventory, and its IDs remain explicit private-materialization obligations; these native owned entries must not provision empty replacement data. Legacy external mounts without a recorded logical binding still require explicit destination mappings.

Preparation preserves path spelling, including non-UTF-8 and symlink/parent components, without opening files, resolving source-host state or provisioning resources. Missing, extra or wrong-kind bindings fail with redacted diagnostics; shared input expansion is bounded. Unknown inventory cannot partially replace destination mounts or routes. Destination inputs remain outside portable metadata, and supplying a path never grants a saved relaxation or proves full-resume identity.

This completes native storage-reference preparation, not backing restoration or whole-config activation. The shared destination path resolver, physical resource checks, mandatory policy and individual approvals, private owned-payload materialization, captured mount/socket identity checks and every activation consumer remain required. The saved-config writer and required-extension activation remain disabled.

`prepare_listener_configuration` similarly turns complete listener selection into native port inputs. Every surviving selected listener must have a destination; an explicit mapping for one shared consumer cannot discard another transport/service. Known builtin/empty inventories replace lower ports, whereas unknown or unrecorded inventories cannot mutate destination networking. Ephemeral port zero and independent TCP/UDP listeners retain their native meanings. Socket allocation, mandatory destination policy and full-resume NIC/connection checks remain required; preparation opens no listener and does not authorize traffic.

## Combined configuration preparation

`prepare_saved_configuration` coordinates the family preparers against one validated immutable document, descriptor, destination patch and restore context. It validates original metadata and legacy projections before fresh mode, clears or explicit overrides can mask them. Only selected active fields contribute default demand; pending fields remain validated but cannot supply defaults or add activation requirements. Full resume additionally requires independently established geometry, guest policy and captured binding inventory, which optional selection cannot discard.

The destination supplies one typed binding registry. A text binding shared by future command defaults and host substitution has one value, while replacing only the command field preserves the substitution requirement. Logical listener inputs participate before matching explicit native listeners, so they can disambiguate repeated guest service identities. The registry is bounded before copying shared material, rejects unused or incompatible inputs, and retains captured-only inputs for subsequent physical identity checks.

An unresolved environment/store credential source can prepare a host substitution reference but is never ready command text. Future command/init requirements remain explicit gaps; an immediate command/init/script consumer refuses until its text is resolved. Empty supply gaps establish only logical input coverage, not credential resolution, backing identity or permission to activate. The returned plans retain each family's unknown, approval, materialization and full-state obligations, and no partial result escapes a preparation failure.

The network and whole-destination input assemblers below build on this combined preparation without enabling the feature. Effective-consumer admission, file/credential loading, policy and identity enforcement, persistent deferred defaults, coherent last-active capture and every launch/exec integration remain required. The writer and activation path stay disabled.

## Combined native network inputs

`SavedConfigurationPlan::network_inputs()` combines the prepared policy, gateway references, listener inventory and secret substitution inputs into one native network value. It validates every family before returning anything; unknown policy/resource/secret/listener observations cannot produce an apparently complete partial configuration. Resolved destination interface defaults and sparse explicit overrides remain inputs to the later allocator and captured-identity checker, never portable source identity.

Native optional containers retain their meaning: in saved mode, a recorded builtin DNS/TLS/secret section produces an absent container unless an explicit destination section is supplied; a recorded concrete section or explicit empty section remains present. Fresh mode keeps the presence of destination DNS/TLS policy defaults, even when the artifact recorded a builtin choice. Policy fields and resource siblings are composed together before restoring this presence, so resolver/CA/proxy inputs cannot erase policy and policy defaults cannot erase supplied resources. Guest trust certificates remain separately available through the gateway plan because `NetworkSpec` has no guest-certificate-file field.

Composition performs no file loading, credential lookup, DNS resolution, socket allocation or activation. It retains the original approval, full-state and binding obligations in the immutable plan; an unresolved substitution source does not make a future command binding ready. Its returned value is input to destination admission and must never be exported as the portable saved document. The whole-destination assembler below retains those obligations. Materialization, policy/full-state/deferred enforcement, capture/retention and all public launch/exec consumers remain required before enabling the saved-config writer and required extension.

## Whole-destination inputs

`SavedConfigurationPlan::into_destination_inputs()` composes runtime, resources, execution metadata, network and storage/IPC inputs into `SavedDestinationInputs`. It owns both the native inputs and the same immutable preparation plan. It has no serialization or consuming conversion into a bare `SandboxSpec`; consumers must retain the plan through materialization, admission and persistence. The read-only `spec_inputs()` view is not proof that all future defaults are ready and must not be passed directly to launch.

Destination-only fields (name, root source, requested patches, pull/deployment policy, ephemeral ownership and reserved identity labels) are pinned from the original destination inputs. Saved metadata does not supply them. The assembler does not reapply the whole raw patch afterward, which could revive removed CMD, discard bound resource inventories or route exact scripts through the ordinary writer. Root/dependency compatibility, patch eligibility and all existing destination validation still need enforcement before side effects.

Unknown immediate inputs refuse before any candidate escapes. Hostname, clock and script backing are checked for the current activation. A new initial command also requires complete command defaults; cold boot requires init inputs. Full resume keeps its captured PID 1 and never places a cold-boot init request in native activation inputs. Future command/init requirements remain on the owned plan when they are not needed now; an empty native field does not resolve a missing binding or unknown observation. Each later command/boot must use the plan's availability checks and retained references. Exact script bytes and modes remain separate from ordinary runtime script strings.

Composition grants no approval, opens no files or sockets, resolves no credentials and admits no captured backing. Full-state, mandatory policy, saved relaxation, host-resource and deferred requirements all survive unchanged. Coherent capture/retention, actual backing materialization, mandatory enforcement, durable deferred requirements and every public launch/exec path remain required; capture and activation stay disabled.

## Local registered-script backing

On Unix, `capture_runtime_scripts` observes registered files below an already pinned runtime directory with the portable schema’s limits. It delegates to the filesystem crate’s `CapturedRuntimeScripts`, which is reusable by the runtime inside its checkpoint pause without introducing a runtime-to-SDK dependency. It holds inode references and reads exact bounded UTF-8 bytes plus guest-visible ownership and permissions using the filesystem backend's strict metadata overlays. Host `stat` permissions alone are insufficient: a guest can have mode `0000` while the host retains owner access. Script and runtime directory metadata are retained too. Symlinked files/directories, special files, incompatible virtual types, privileged mode bits and oversized inputs refuse; diagnostics omit names, paths and content.

The caller must hold the coherent source mutation/capture guard. Revalidation checks directory identity and metadata, file identity, content, timestamps and guest metadata, but cannot create atomicity across concurrent writers by itself. These observations are not serializable and are not the portable document: capture exclusions/binding substitution, source generation and full-state closure checks still apply. Unregistered runtime files and arbitrary captured open handles are not covered.

`stage_exact` writes a separate temporary runtime directory beneath a caller-owned private staging parent, with no replacement of an existing runtime. It preserves exact bytes and guest metadata, verifies them, and revalidates the source before returning. Host permissions remain private independently of guest modes. Relative staging parents are pinned to the call-time directory without collapsing symlink/parent components. Dropping the returned directory cleans it up even after cwd changes; late failure or observed source change discards the staged files. Nothing is executed or installed. This is local capture/staging infrastructure, not archive restoration, source-deleted support, or launch integration. Windows metadata support, portable backing evidence, capture sanitization, runtime ownership transfer, full-state admission and durable consumer integration remain required; feature activation stays disabled.

`RuntimeConfigurationPlan::stage_disk_scripts` materializes selected portable or destination-bound bytes without a surviving source directory. It writes exact UTF-8 content and selected guest modes, with root ownership for newly created guest files and directories, while host permissions remain private. Names, duplicates, count/byte limits and privileged mode bits are checked before filesystem effects; verification reopens the staged filenames and checks their bytes, metadata and directory identity. Input failure, staging failure or an observed change discards the complete temporary directory. Relative staging parents retain call-time symlink/parent semantics through cleanup.

This is cold-boot preparation, not a full-resume backing repair or an activation permit. Full-resume plans refuse even when their selected script inventory is empty or matches recorded content. Unavailable inputs refuse, destination bindings remain separate from the portable record, and ordinary script wrapping is not rerun. Adopting the staged directory into runtime ownership, coherent capture, complete destination admission, full-state handle identity, Windows support and public launch integration remain required before feature activation.
